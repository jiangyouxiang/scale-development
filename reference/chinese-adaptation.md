# 中文适配方案

本 Skill 的多智能体生成层替代了 AIGENIE 原版的 LLM 生成。因此在中文适配方面，
约束条件从「AIGENIE 的参数注入」变为**各 LLM agent 角色的 prompt 约束**。

> ⚠️ **中文本身就是"三重越界"之一**：原论文（Russell-Lasalandra et al., 2026）的实证
> 验证**全部为英文**，零非英文样本。把整套 in-silico 流程用于中文，意味着论文的
> "in-silico≈应答结构效度"论断**无中文实证基准**支撑。中文结果尤其需要真实中文样本追验证。
> 详见 `reference/methodological-boundaries.md`。

## 总体原则

中文量表开发中，多智能体生成层**全部使用中文**交流：
- 策略师/出题者/审查者/整合者的指令和工作语言 → 中文
- 题项内容 → 简体中文（`statement` 字段值）
- 但 `type`（维度名）和 `attribute`（属性名）保留构念 JSON 中的值（可中文）
- 题项 JSON 的键名保持英文（`type`/`attribute`/`statement`）
- `generation_session_log.md` 及审查报告 → 中文

## 各角色的中文约束

### 策略师
- 计划文本为中文
- 需明确标注每个属性下的题项应用中文编写规范（见下方规范）
- 对于中文特有的问题（如四字成语、翻译腔），在计划中给出具体规避指示

### 出题者
- 角色 prompt 开头需强制注入：「必须用规范的简体中文撰写所有题目」
- 属性（attribute）值来自构念 JSON，可能为中文或英文——出题者应保持原样
- 题项文本的撰写规范见下方「中文编写规范」

### 审查者
- 审查报告为中文
- 除了常规审查维度，额外检查：
  - 是否含台湾/香港用语（如「滑鼠」「計程車」）
  - 是否有翻译腔（过长定语、「被」字滥用）
  - 是否适合中文目标人群的语言水平

### 整合者
- 会话日志为中文
- 题项 CSV 的 `statement` 为中文，`type` 和 `attribute` 保持构念原始值

## 中文编写规范（供各角色参考）

```
【中文编写规范】
1. 使用简体中文，避免繁体字和异体字
2. 避免四字成语、歇后语等口语化或文学化表达
3. 避免双重否定（如"不是不"、"不得不"）
4. 主语明确，避免省略主语；统一使用第一人称"我"
5. 避免歧义量词（如"一些"、"很多"），改用明确的频率/程度描述
6. （仅在包含反向题时适用）反向题的表述需自然，避免生硬加"不"字
7. 题项长度控制在 15–30 个中文字符
8. 每个题项为单一陈述句，避免复合句与双重内容
9. 避免社会期许性偏差明显的表述
10. 反向题的包含与比例由用户在生成前决定（见决策门 3）；**默认不含反向题**，
    仅当用户明确选择包含时才按其指定比例编写
```

完整版本见 `assets/chinese_prompt_notes.txt`。

## 反向题在嵌入管线中的已知风险（仅当用户选择包含反向题）

反向题在语义空间里是"同一主题的否定"，与嵌入相似度天然冲突。原论文全程**零反向题**，
故此风险无论文实证基准可依。若用户选择包含反向题，需注意：

- **UVA 风险**：正题与其反向题嵌入高度相近（wTO 高），可能被判为冗余而**删除其一**，
  造成正/反不成对。
- **EGA 风险**：正/反题可能被分入**不同社区**，制造**方法因子伪结构**，拉低 NMI。

**人工复核要求**：包含反向题时，务必**复核被 UVA 删除的正/反成对题**，并核查 EGA 社区
是否按"正/反"而非按内容分裂。详见 `reference/methodological-boundaries.md` 第五节。

## 嵌入模型选择（中文验证层用）

语义相似度计算（UVA 去冗余、维度聚类）应优先支持中文的嵌入模型：

| 模型 | provider | 中文表现 | 备注 |
|------|----------|---------|------|
| `text-embedding-3-small` | OpenAI | 良好 | 默认，性价比高 |
| `text-embedding-3-large` | OpenAI | 更好 | 维度更高，成本略高 |
| `jina-embeddings-v3` | Jina | 良好 | 需 `jina.API` |
| `BAAI/bge-large-zh-v1.5` | HF | 中文专用 | 需 `hf.token` |

注意：**中文题项进入 GENIE 嵌入后，UVA/EGA/bootEGA 全部基于嵌入向量，
与语言无关**——只要嵌入模型支持中文，验证管线即正常工作。

## 文化适配校验清单

多智能体生成的人工复核环节应检查：

- [ ] 是否含西方文化特定概念需本地化
- [ ] 集体主义 vs 个体主义语境是否匹配目标人群
- [ ] 是否有翻译腔/欧化句式
- [ ] 反向题是否自然，未生硬加"不"
- [ ] 量词与频率词是否明确无歧义
- [ ] 是否符合目标人群的语言水平
- [ ] 是否适合中文作答习惯（如避免极端选项过多）
## 题目生成与量表验证的边界

中文题目由多智能体生成并经过审查后，只能说明题目草案已形成，不等于量表已经完成心理测量验证。
进入 AIGENIE 前必须通过嵌入来源决策门：

- 有 `OPENAI_API_KEY` 时可选择 OpenAI，但不得自动替用户选择。
- 没有 OpenAI key 时，可选择 Jina、HuggingFace、本地模型或已有 `embedding.matrix`。
- 选择 `skip` 时，必须保留 `scale_validated=false`，并提示后续需要运行 GENIE。
- 中文嵌入模型应在目标语言上有合理表现；模型选择改变后，应在解读中记录。
- 即使 GENIE 成功，结果仍属于 in-silico 语义/冗余筛查，不替代真实中文样本上的 EFA/CFA、
  信度、测量不变性和内容效度研究。
