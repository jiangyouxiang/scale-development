# 构念定义规范

**构念定义的精确程度是多智能体生成质量的最大瓶颈。** 模糊的构念描述会让策略师规划
失当、出题者写出表面效度高但内容效度低的题项。本文档规定构念定义的标准结构与质量要求。

## 核心原则

1. **操作化定义优先**：不要只给抽象定义，要给出可观测、可作答的边界条件。
   - 差：「自我效能感是对自己的信心」
   - 好：「学术自我效能感是个体对自己完成特定学业任务（理解课程内容、完成作业、
     通过考试）能力的信念判断，不包括对结果价值的评价」
2. **维度 = 构念的子面**：每个维度应是理论上可区分且内涵不重叠的结构面。
   维度名将作为多智能体生成中 `type` 字段、验证管线中 GENIE 的分组依据。
3. **属性（attributes）撑开维度内涵**：每个维度 ≥2 个唯一属性；属性是维度的不同侧面，
   不是同义词。多智能体生成的策略师会根据属性分布制定题项生成计划。
4. **参考题项定风格**：`sample_items` 作为风格模板（质量、句式、框架），策略师和
   出题者会参考，但不会复制内容。

## JSON Schema

```json
{
  "construct_name": "构念名称",
  "definition": "操作化定义，含边界条件",
  "theoretical_framework": "理论框架",
  "dimensions": [
    {
      "name": "维度名",
      "description": "维度描述",
      "attributes": ["属性1", "属性2", "属性3", "属性4"],
      "sample_items": ["参考题项1", "参考题项2"]
    }
  ],
  "response_format": "Likert 5 点",
  "target_population": "目标人群",
  "item_count_per_dimension": 60,
  "language": "zh-CN",
  "reverse_items": { "include": false, "ratio": "0" }
}
```

字段约束：
- `dimensions[].attributes` —— 每维 ≥2 个**唯一**属性（同维内不可重复；跨维可重复）
- `dimensions[].name` —— 每个维度名唯一
- `item_count_per_dimension` —— 建议 ≥60，低于此前削减后可能不足 4 题
- `language` —— `zh-CN`（策略师/出题者以中文工作）或 `en`
- `reverse_items` —— `{ include, ratio }`。**默认 `include:false`**（原论文零反向题，且反向题
  在嵌入管线中有冗余/方法因子风险）；是否包含与比例须经用户在生成前确认（决策门 3），
  详见 `reference/methodological-boundaries.md` 第五节

## 常见错误

- ❌ 维度之间高度重叠（神经质 vs 焦虑），导致 EGA 无法区分 → 低 NMI
- ❌ 属性是同义词堆砌（开心/快乐/愉悦），多智能体生成题项高度冗余 → UVA 大量删除
- ❌ 定义过宽（"幸福感"不限定主观/心理/社会），策略师规划失当
- ❌ `item_count_per_dimension` 设太小（<30），削减后剩题不足 4 个无法分析
