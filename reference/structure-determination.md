
# 确定测评结构：四条路径

量表开发的第一个、也是最关键的决定，是**维度结构**——构念分几个维度，
每个维度由哪些属性（attributes）构成。结构错了，后面生成再多题、削减再
干净也没用。

本 Skill 支持四条确定结构的路径。**先用弹出选择题与用户确认走哪条**（也可组合，如文献 + 访谈
三角互证）。四条路径最终都收敛到同一产物：

> 确定的 **构念名 + 维度（= `type`，多智能体生成的维度分组依据）+ 各维属性（attributes，每维 ≥2 个唯一值）**，
> 落到 `assets/construct_template.json`，再进入第 2 步。

每条路径在形成结构初稿后，都必须 **⛔ 回显给用户确认/修改**，再继续。

---

## 统一报告交付规范（路径 A/B/D 必须）

路径 A/B/D 的正式交付物不再只是资料摘要，而是一份**学术论文式维度结构论证报告**：

- `dimension_structure_report.md`：Markdown 正文，保留可追溯引文、表格与附录链接。
- `dimension_structure_report.docx`：给用户阅读/归档/改写论文使用的 Word 版本。
- 支持性文件（可选）：`literature_review.md`、`interview_analysis.md`、`triangulation_summary.md`、编码表、检索记录等。

写作要求：

1. **论文式结构**：题名、摘要、关键词、引言、理论背景/文献综述、资料与方法、构念界定、竞争模型、证据整合、推荐维度结构、局限、结论、参考文献。
2. **正文引文**：采用 APA-like 文内引用，例如 `(Author, Year)` 或 `（作者，年份）`；同一关键结论至少给出可追溯来源。
3. **参考文献**：列出作者/机构、年份或日期、题名、来源、DOI/URL（如有）、访问日期（网页来源）。
4. **证据表**：至少包含“来源/材料、支持的维度或属性、证据摘要、证据强度、备注”。
5. **推荐结构表**：至少包含“维度名、操作化定义、属性、证据来源、置信度、需用户确认的问题”。
6. **访谈材料**：代表性引语必须匿名化；不得暴露个人身份信息。

报告模板与检查清单见 `reference/dimension-structure-report.md`。Markdown 转 Word 可用：

```powershell
python .\scripts\md_to_docx.py .\dimension_structure_report.md .\dimension_structure_report.docx
```

> ⛔ 路径 A/B/D 未产出 `dimension_structure_report.md` 与 `dimension_structure_report.docx`，
> 或用户未确认推荐结构时，不得写入最终 `construct_template.json` 并进入生成层。

## 路径 A：文献驱动（literature-driven）

**适用**：构念有成熟理论基础，或已有公开量表 / 综述可循。

**目标**：通过系统检索文献，归纳出有实证或理论支持的维度结构。

### 步骤

1. **确认检索范围**（弹出选择题 + 必要简短输入）：构念名、目标人群、语言、年限、是否限定权威来源/数据库倾向（如中文用 CNKI 类、英文用经典量表与综述）。
2. **多源检索**：用 WebSearch，或调用 `deep-research` skill 做扇出检索 + 来源核验。重点找：
   - 构念的**权威定义**（不同学派的界定差异）
   - 主流**理论框架/模型**
   - 已有**量表的因子结构**（各维度名、维度下的题目侧重）
3. **形成学术化报告** `dimension_structure_report.md`，至少含：
   - 构念定义综述（汇总不同来源的界定，标注引用）
   - 理论框架对比（各模型的维度划分并列）
   - 竞争性维度模型比较（如单维/多维/层级模型）
   - **证据整合表**：来源 × 维度，看哪些维度被反复验证
   - **推荐维度结构**：每个维度 + 该维属性，并注明每个维度的文献来源
   - 参考文献（APA-like）
4. **转换 Word**：生成 `dimension_structure_report.docx`。
5. **⛔ 用弹出选择题回显推荐结构给用户**确认/调整。

### 注意

- 区分「有实证支持的维度」与「仅理论假设的维度」，在报告中标注。
- 避免单一来源；维度划分有分歧时，把分歧呈现给用户决策，不要替用户拍板。
- 属性（attributes）应来自文献中对该维度的具体描述/子面，而非临时编造。
- 引用要可追溯（标题/作者/年份/链接），便于论文方法部分撰写。

## 路径 B：访谈驱动（interview-driven）

**适用**：探索性构念，缺乏成熟量表，需要从一手质性资料**自下而上**提炼结构（扎根理论式）。

**输入**：用户提供的访谈逐字稿 / 开放式问卷文本（文本文件）。

### 步骤

1. **确认资料范围**（弹出选择题 + 必要简短输入）：访谈对象、样本量、构念焦点、资料是否已脱敏。
2. **开放式编码（open coding）**：逐段从语料中提取意义单元 → 贴标签形成**初始概念（codes）**。
3. **主轴编码（axial coding）**：归并语义相近的初始概念为**类属（categories）**——类属即候选**属性（attributes）**，相关类属的聚合即候选**维度**。
4. **选择性编码（selective coding）**：围绕核心构念整合各维度，形成结构。
5. **形成学术化报告** `dimension_structure_report.md`，至少含：
   - 资料与方法：样本、访谈来源、脱敏说明、编码步骤
   - **编码表**：原始语句 → 初始概念 → 类属 → 维度（保持可追溯）
   - 各维度的命名、定义与属性
   - 饱和度/频次说明（哪些主题反复出现）
   - 每个维度/属性的**匿名化代表性引语**（可作为 `sample_items` 的风格参考）
   - 质性研究局限与下一步验证建议
6. **转换 Word**：生成 `dimension_structure_report.docx`。
7. **⛔ 用弹出选择题回显维度结构给用户**确认/调整。

### 注意

- 保持与原始语料的可追溯性：每个维度/属性都应能回指到具体语句。
- 编码带主观性：必要时建议双人独立编码 + 一致性核对，或请用户复核关键归并。
- 代表性引语进入 `sample_items` 时要清洗（去口语化、保护隐私），它们只作风格模板，AIGENIE 不会照搬其内容。

## 路径 C：用户直接输入（user-specified）

**适用**：用户已有明确结构——来自既有理论、已发表量表，或专家共识。

### 步骤

1. **引导录入**：请用户给出构念名、操作化定义、各维度（名 + 描述）、每维属性（≥2）。
2. **快速质检**：
   - 维度之间是否概念互斥（避免内容重叠导致后续 NMI 偏低）
   - 每个维度的属性是否足够具体
   - 是否有维度其实是结果变量/前因变量，而不是构念本身的一部分
3. **整理回显**：输出结构表给用户确认；必要时写 `structure_confirmation.md`。
4. 用户确认后再写入 `construct_template.json`。

### 注意

- 不要擅自扩展用户未给出的维度；若发现缺口，提问而不是补编。
- 若用户结构来自已发表量表且只想**验证/精简已有题目**，应改走 `GENIE()`（见 SKILL 决策树），而非通过本路径重新生成。
- 路径 C 不强制 `.docx`，但用户需要正式留档时可按同一模板输出。

---

## 路径 D：文献+访谈三角验证（literature + interview triangulation）

**适用**：既有文献可参考，但目标人群/语境可能有本土化或新情境差异；需要用一手资料检验文献结构。

**目标**：独立走 A 和 B 两条证据链，再通过三角比对合成一份有证据权重的学术化报告。

### 步骤

1. **先分别完成 A 与 B 的分析**：保持两条证据链相对独立，避免文献框架先入为主压制访谈新发现。
2. **三角比对与合成**：逐一比对文献维度与访谈主题，按类型标注每条证据：

   | 标记 | 含义 | 处理 |
   |------|------|------|
   | 🔵 强一致 | 文献维度与访谈主题高度一致 | 优先保留为核心维度/属性 |
   | 🟢 文献有、访谈弱 | 文献支持但访谈中较少出现 | 标注为理论保留或候选维度，询问用户 |
   | 🟠 访谈有、文献弱 | 访谈中强出现但文献较少 | 标注为情境特异维度，需专家确认 |
   | 🔴 两源矛盾 | 文献维度与访谈分类冲突 | **提请用户决策**，说明各自合理性及倾向 |

3. **形成统一报告** `dimension_structure_report.md`：正文同时包含文献证据、访谈证据、三角对比表、最终推荐结构与局限。
4. **转换 Word**：生成 `dimension_structure_report.docx`。
5. **⛔ 用弹出选择题提交完整比对给用户**（Word 报告 + 推荐结构 + 关键待决问题）确认/调整。

---

## 确定结构之后

用户确认后：

1. 把结构写入 `construct_template.json`。
2. 路径 A/B/D 的 `dimension_structure_report.md` 与 `dimension_structure_report.docx` 作为构念效度证据链保留；支持性报告可作为附录。
3. 继续环境就绪（第 3 步）→ 生成模式决策门（第 4.0 步）→ 多智能体或显式兜底生成（第 4 步）→ GENIE 验证（第 5-6 步）。
